# scene_change（シーン切り替えトランジション・ゲーム実装用）

| | |
|---|---|
| コマ画像 | `frames_scene_change/scene_change_00.png` … `_31.png` |
| データ | `scene_change.json` |
| コマサイズ | **1672 x 941**（`background/shibuya_001` と同寸・16:9） |
| 長さ | 32F / 1.333s・**ループしない** |
| 形式 | RGBA PNG（合計 10.7MB） |
| 差し替え位置 | **F21 - F22**（`coverFrames`） |
| プレビュー | `scene_change_demo.html`（ブラウザ） / `../../scene_change/scene_change.blend`（Blender） / `../../gifまとめ/scene_change.gif` |

**シート PNG はありません**（`sheet` は `null`）。1 コマが 1672x941 あるので、
他のクリップのように 1 枚のシートにすると 13376x3764 ＝ 5000 万画素・VRAM で 200MB になり、
トランジション 1 本にその常駐は割に合わないためです。`frameDir` の連番 PNG を直接読んでください。

## 使い方

1. 生の画面の上にこの 32 コマを 24fps で順に重ねる（アルファ合成）。
2. **F21 か F22 のあいだに裏のシーンを差し替える**。この 2 コマはアルファが全面 255 で
   下の絵が透けず、画素の 96% が輝度 200 超・平均 249 の白飛びなので差し替えは見えません
   （残り 4% は白飛びの**上**に乗っている破片と紙吹雪です）。
3. 最後まで再生したらオーバーレイを捨てる。

アルファは全画面一律のフェード（F0-F3 で入り、F29-F31 で抜ける。値は JSON の `alpha`）を
**PNG に焼き込んであります**。生の画面にそのまま重ねるだけで入りと抜けが繋がります。
アルファを見ない実装なら RGB だけ使ってください（入りが即時の黒になるだけで、絵は同じです）。

## Blender で確認する

`blender/scene_change/scene_change.blend` を開いて**スペースで再生**するだけです
（フレーム 1-32・24fps・カメラビュー・マテリアルプレビュー）。

- 差し替え**前**は背景なし（素の黒）
- `bg_after` … 差し替え**後**の背景（`background_white`）。**Blender フレーム 22（=コマ21）で
  出る**ようにキーが打ってあるので、再生して切り替わった瞬間が見えなければ
  白飛びがちゃんと隠せている、という確認がそのままできます。
- `fx` … トランジションの 32 コマ（イメージシーケンス）

裏の絵は `scene_change_blend.py` の `BG_A` / `BG_B` で差し替えられます（`None` で黒）。
`scene_change_demo.html` も同じで、先頭の `SCENES` が差し替え前後の絵です。

組み直しは `blender/scene_change/scene_change_blend.py`（Blender のテキストエディタから実行、
または `E:\blender.exe --python scene_change_blend.py`）。**差し替えフレームは JSON から
読んでいる**ので、コマ構成を変えても書き写し直す必要はありません。

**このシーンは色を素通しにしてあります**（画像を Non-Color、ビュー変換を Raw、
`filter_size=0`、TAA 1 サンプル）。既定のままだと Blender は画像をリニアに直してから
合成するので、**sRGB のまま合成するゲームや HTML デモと結果が食い違います**
（アルファ 0.45 のコマでレンダー平均 96 対 正解 69）。素通しにすると
2D エンジンの合成と一致し、実測で平均差 0.1〜0.4/255・最大 1.5/255（8bit の丸めのみ）です。
**見た目を判断するときは必ずこの設定で見てください。**

## 素材との関係（なぜ描き直したか）

素材は `scene_change/frame_01..10.png` の 10 枚ですが、**324x460 の縦長**です。
ゲーム背景は 1672x941 の 16:9 なので、そのまま全画面に使うと約 5 倍拡大＋上下カットになり、
輪郭がすべて溶けます。そこで **10 枚からパラメータを実測して 1672x941 で生成し直しました**
（`../../scene_change/scene_change_render.py`）。素材は「見た目の正解」として使っています。

合わせた実測値は 2 つです。

**(1) 筋の向き（構造テンソルの向きを半径方向と比べた「接線性」）**

| | 素材 | この出力 |
|---|---|---|
| 渦のコマ | 0.82 - 0.87 | 0.79 - 0.81（F7-F13） |
| 放射のコマ | 0.34 - 0.37 | 0.34（F19） |
| 静止のコマ | 0.70 - 0.74 | 0.66（F0）＝ 2/π = 0.637 ≒ 向き無し |

筋は粒子の軌跡なので、**半径速度 / 接線速度がそのまま筋のピッチ**になります。
素材の接線性から逆算すると渦で 0.6・放射で 2.8 なので、回転を先に立ち上げ、
拡大を後から追い越させる 1 つの運動で 10 枚すべてが説明できました。

**(2) 明るさと被覆率**

| | 素材 | この出力 |
|---|---|---|
| 渦のピーク | コマ5: 平均 79 / 32超 0.55 / 128超 0.25 | F14: 74 / 0.57 / 0.22 |
| 放射 | コマ7: 130 / 0.76 / 0.48 | F19: 145 / 0.94 / 0.52 |
| 白飛び | コマ8: 239 | F21: 249 |

色（`PALETTE`）は frame_01 の連結成分から拾った RGB をそのまま使っています。

## 中身の構成

レイヤは 3 枚で、合成の仕方が違います。

- **stars**（加算）… ワープの筋。重なると白く飽和します。
- **debris**（アルファ合成）… 閃光で飛び散る破片。灰色 1 色で、白背景では暗く・黒背景では
  明るく見えます（素材のコマ8 と コマ9 が同じ灰色で両立するのはこのためです）。
- **confetti**（アルファ合成・最前面）… 素材で唯一ワープに流されていない層。
  コマ4・6・7 でも白い筋の上に有彩の四角が乗っているので、前面の別レイヤだと分かります。

コマ名（`labels`）は calm → spin → swirl → burst → flash → **cover** → fade → debris → calm。

## 作り直す

```
cd blender/scene_change
python scene_change_publish.py
```

`scene_change_render.py` の先頭のカーブ（OMEGA / ZRATE / STARA / FLASH / BGW …）が
すべてのつまみです。コマ数は `N`、解像度は `W, H` を変えるだけで追従します。
`SEED` を変えると粒の配置が変わります。

同じフォルダの `analyze.py` / `geom.py` / `comps.py` は**素材**を測るスクリプト
（輝度・被覆率・彩度／渦の中心とコアと接線性／粒の連結成分と色）、
`measure.py` は**出力**を同じ指標で測って素材と突き合わせるスクリプトです
（`python measure.py ../develop/scene_change/frames_scene_change`）。
見た目を変えたときは必ずこれで数字を確認してください。

publish は **完全被覆のコマを名前ではなく実測で選び**、1 つも無ければ止まります
（ここが破れるとシーンの差し替えが見えるため）。
