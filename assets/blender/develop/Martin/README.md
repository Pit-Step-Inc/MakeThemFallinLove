## walk（正面歩き・全身・9コマ中4コマを再生）

**素材の制約を先に書きます。** どちらの足が前かをシルエットの下端（正面なので手前の足が低い）で
判定し、腕の振り（脚と逆に振れる）で裏を取ると、**右足前が7枚・左足前が2枚**でした
（右足前の7枚は左手が大きく832〜982px／右手586〜653px、左足前の2枚は逆）。
歩行サイクルは半周期ずつ均等な枚数が要るので、このままでは組めません。

さらに**右足前の7枚は互いにほとんど同じポーズ**です。脚の領域の平均絶対差は、

| | 平均絶対差（/255） |
|---|---|
| 右足前の7枚どうし | 10.3〜18.1（中央値13.9） |
| 左足前の2枚どうし | 21.4 |
| 左右グループ間 | 26.9〜33.9 |

つまりこの9枚は「歩きの9姿勢」ではなく**「1姿勢の7テイク＋別姿勢の2テイク」**で、
**すれ違い（passing）の姿勢がどこにもありません**。

### 選んだ4コマ
- 左足前の2枚（コマ2・7）は互いに21.4離れているので、そのまま半周期の2姿勢に使う
- 相方は**左右反転で対応付け**た。コマ2を反転するとコマ6に最も近く（19.2）、
  コマ7を反転するとコマ8に最も近い（23.0）。コマ6と8は7枚の中で最も離れた組（18.1）でもあるので、
  右の半周期がちゃんと動く

→ **2（左接地）→ 7（右足が振り出される）→ 6（右接地）→ 8（左足が振り出される）→（ループ）**

9枚とも書き出してあるので、予備テイクは `walk_prep.py` の `CYCLE` を書き換えれば差し替えられます
（JSON の `played` / `spare`）。全部再生すると片方の半周期が7枚・もう片方が2枚になり、
**歩きではなく足を引きずる動き**になります。

### 作り
Catherine の walk と同じです（詳細は `../Catherine/README.md`）。全身は凍結できないので
フィットを詰めて全コマ再生し、そのうえで縦の伸縮でプロポーションを揃えます。

- **スケールは実測**: 眼鏡と腰（グレーTの裾＝ジーンズの上端）の2枠を別々に位置決めし、
  その**間隔の比**をスケールにする。**眼鏡はこの素材でいちばん確実なランドマーク**です
- **縦だけ区分的に伸縮**: 目より上は素のまま、胴は目→ジーンズ上端が全コマ平均に、
  脚は半周期の同じ位置どうしが同じ長さに。写像は連続なので継ぎ目は出ません
- 結果: 胴のばらつき 1.7% → **0.6%**、靴底のばらつき 27 → **22px**、
  頭は止まっている（**目のばらつき x 2.2px・y 1.3px**）

### テンポ
接地7フレーム・振り出し5フレームで **24F＝1.00秒＝毎分120歩**。
**Catherine の walk と同じ歩調**なので、並んで歩かせても合います。
ただし4ポーズなので1枚あたり292ms／208msと長く、Catherine の10ポーズより粗く見えます。

### なめらかにするには素材が要ります
**左足前をあと3枚ほどと、すれ違いの姿勢（両足が前後に近い瞬間）を数枚**足せば、
Catherine と同じ10ポーズの歩きに組めます。今の9枚では2姿勢しか含まれていないため、
これ以上は詰められません。

## コマ番号の意味
- smile     : 0=真顔 1=微笑み 2=目を細める 3=笑顔 4=口を開けて笑う 5=大笑い
- surprised : 0=真顔 1=気づく 2=反応 3=口が開く 4=驚き 5=驚き（大）
- talk      : 20枚の口パクシーケンス。作画順にそのまま再生
              （1枚あたり2フレーム保持＝**毎秒12枚の早口**）
              JSONの hold を 3 にすると毎秒8枚の落ち着いたテンポ、4 でゆっくりになります
              動くのは口だけ。まばたきはコマ7の1枚のみ（JSON の blinkFrame）で、
              このコマだけ3フレーム保持（blinkHold）。2フレームだとこのテンポでは
              ちらつきに見えるため。元の20枚は6枚が閉じ目で毎秒2回以上まばたきしていました
- talk01    : 0=口を閉じる 1=少し開く 2=大きく開く 3=開く(角度違い) 4=小さく開く 5=閉じる
              （両手ポケットのまま喋る。口だけ動くので保持2〜3フレームの速いテンポ）
- talk02    : 0=両手ポケット 1=右手を上げる 2=両手を開く 3=胸に手＋差し出す
              4=人差し指を立てる 5=手を差し出す
              （身振り付き。ジェスチャーが読める保持5〜8フレーム）
- talkhand  : 手を上げて喋る。0/6=口を閉じる 1=少し開く 2/5/7=中くらい 3=大きく開く
              4=中くらい＋目を閉じる（唯一のまばたき）
              8枚は「同じポーズの別テイク」で描き順の口パクではないため、
              タイムラインはこちらで組んでいます（JSON の timeline）。
              動くのは口だけで、頭・髪・体・上げた手は全コマ完全に同一画素
- happy     : 喜ぶ。0〜3=手を差し出す（0は口を閉じる） 4=手を下ろす
              5〜9=拳を上げていく 10=拳を高く上げる 11=両腕をV字に
              12/13=両腕を大きく広げる 14=ニュートラル（腕を下ろす）
              **これだけは体が動きます**（ポーズの進行そのものが素材のため）。
              タイムラインは「構え→拳を2回突き上げ→両腕を広げる→戻る」で組んでいます
- anger     : 怒る。0/1/2/8/9=口を閉じたしかめ面（5枚とも描き分けが少しずつ違う）
              3=わずかに開く 7=小さく開く 4=中くらい 6=大きく食いしばる 5=怒鳴る（最大）
              10枚は「同じポーズ（両手ポケット）の別テイク」で、変わるのは顔だけ。
              動くのは口だけで、髪・眼鏡・上着・手は全コマ完全に同一画素（差分は2248pxのみ）。
              タイムラインは「しかめ面→顎を噛みしめる→振りかぶる→怒鳴る→2回どなる→戻る」。
              元素材に閉じ目が1枚も無いため**まばたきはありません**
- joy       : 喜ぶ。9/0/8/1/2/3=口を閉じた笑み（だんだん広がる） 4/7=歯が見える
              6=声を出して笑う 5=いちばん大きく笑う。**5と6には頬の赤みが付きます**
              （JSON の blushFrames）。10枚は「同じポーズの別テイク」で変わるのは顔だけ。
              動くのは口と頬の赤みだけで、それ以外は全コマ完全に同一画素（差分は3635px）。
              タイムラインは「微笑み→広がる→開く→笑う→2回ゆらす→戻る」。
              コマ5は目を閉じて笑っていますが**眼鏡ごと描き直されている**ため
              まばたきには使えません（後述「joy の位置固定」）
- sadness   : 悲しむ。7/9/0/8/2/1=への字の口（描き分けが少しずつ違う） 3=震え出す
              4/6=開く 5=**涙が出る唯一のコマ**（JSON の tearFrame）。
              10枚は「同じポーズの別テイク」で変わるのは顔だけ。動くのは口と涙だけ
              （差分は1544px）。**涙はコマ5にしか無いので 5↔6 を往復させると点滅します**。
              タイムラインではコマ5を7フレームの連続ブロックで1回だけ出しています
              （しかめ面→口が震える→涙→顔を戻す）。涙と両端以外はすべて保持2フレーム＝
              毎秒12枚で、これ以上短くするには保持ではなくカット数を減らすことになります
- pleasure  : 上機嫌。**口の形が10種類あるのではなく、同じ閉じた笑みが10回描かれている**
              だけで、10枚合わせても 37x9px しかありません。凍結すると残るのは笑みの
              揺れだけになり「呼吸している」ように見えます（差分2817px）。
              広さ順は 9 0 6 2 8 7 1 3 4 5。コマ6には**薄い頬の赤み**が付きます
              （肌との差が10〜25階調しかない／JSON の blushFrame）。
              赤みはコマ6にしか無いので sadness の涙と同じく7フレームの連続ブロックで
              1回だけ出しています（漂う→いちばん広い笑み→戻す→赤み→元へ）。
              **ベースはコマ1**（他クリップはコマ0）
- surprised02 : 驚き（10コマ版）。**surprised とは別クリップで、置き換えではありません**
              （surprised は6コマ・362x724・初回パスの重心合わせ／凍結なし）。
              9/8/0/7/6=小さな「お」の口 1/3/2=開く 4/5=大きく開く。
              **目は差し替えられません**（コマ3/4/5は見開いているが眼鏡ごと描き直されていて、
              縁の重なりが0.67〜0.75／他コマは0.81〜0.87）。そこで**見開いた目のコマ4を
              ベースに固定**してあり、クリップ全体が目を見開いたまま口だけが動きます
              （JSON の baseFrame は 4）。驚きに予備動作は無いので、
              タイムラインは小さい口からいきなり最大へ跳ねて、そこで揺れてから順に下ります
- talk03    : 喋る（10コマ版・両手ポケット）。**talk01 とは別クリップで置き換えではありません**
              （talk01 は6コマ・初回パス）。8/9/0=閉じる 7/1/6/2=小〜中 5/3/4=開く（4が最大）。
              口が10種類あるので本物のリップシンクが組めます。タイムラインは3フレーズ構成で、
              各フレーズは保持2フレーム（毎秒12枚＝早口）で形を混ぜ、区切りで閉じた口に着地。
              **落ち着いたテンポにしたい場合は timeline の保持を全部 2→3 に**（毎秒8枚／
              martin_talk の hold と同じつまみ）。
              一連の10枚組の中でいちばん継ぎ目が楽な素材で、リング上の差は最大11/255

## JSON
```
timeline : [コマ番号, 表示フレーム数] の配列（Blenderのタイムラインと同じ値）
frames   : 1フレーム=1要素に展開済みの配列（index でそのまま引ける）
fps / frameWidth / frameHeight / frameCount / loop / durationSec / labels
```

## 最小実装
```js
const d = await (await fetch("martin_talk01.json")).json();
const img = new Image(); img.src = d.sheet;
let t0 = performance.now();
function draw(now) {
  const f = Math.floor((now - t0) / 1000 * d.fps) % d.frames.length;
  const i = d.frames[f];
  ctx.clearRect(0, 0, d.frameWidth, d.frameHeight);
  ctx.drawImage(img, i*d.frameWidth, 0, d.frameWidth, d.frameHeight,
                0, 0, d.frameWidth, d.frameHeight);
  requestAnimationFrame(draw);
}
img.onload = () => requestAnimationFrame(draw);
```
拡大時は canvas に `image-rendering: pixelated` を付けてください。

## 素材ごとの下処理メモ
- smile     : 元からアルファ付き。単純6等分
- surprised : 背景が黒ベタだったので外周からの塗りつぶしで背景だけ透過。
              黒に合成されて潰れていた縁のアンチエイリアスも復元
- talk      : 5列4段のグリッド。空行・空列からセルを検出し、各セル内で連結成分を取って
              自分の絵だけを残したうえで、**顔の帯を相互相関で合わせて**統一キャンバスへ配置
              （blender/Martin/grid_prep.py）。そのあと口以外を固定する処理を通します
              （blender/Martin/freeze_talk.py）。一括処理は
              blender/Martin/talk_pipeline.py（grid_prep → freeze_talk → シート再生成）
- talk01/02 : 身振りや髪が隣のコマにはみ出すため等分割不可。
              キャラ間の最も細い列で切り、連結成分で自分の絵だけを残し、
              頭の中心を基準に均一キャンバスへ配置（blender/Martin/sheet_prep.py）
- happy     : 5列3段のグリッド。**元からアルファ付き**（赤いグラデ背景はアルファ0）なので
              抜きは不要。ただし下段は腕を広げていて**隣のセルに食い込んでいます**
              （コマ12の右手は x903〜958、つまり「自分のセル」の外）。
              **縦に切ってはいけません** — どこで切っても誰かの手が落ちます。
              α>96 で連結成分を取ると各行ちょうど5個の塊になり、x範囲は重なっていても
              図形としては別物なので、これで手ごと丸ごと取れます。そのあと
              α>32 の柔らかい縁へ「早い者勝ち」で4回膨張させて輪郭を回収。
              位置合わせは**頭のテンプレートマッチ**。腕は動くのが正解、腰はコマごとに
              描き直されていて相関が最大30pxも迷うので、剛体なのは頭だけです。
              素材のアルファは最大254（体は253）で完全不透明にならないため、
              240以上を255にスナップしています（blender/Martin/happy_prep.py）
- talkhand  : シートではなく 1122x1402 の**別々の8枚**（Martin/talk_02/）。
              別生成なので位置だけでなく**拡大率も最大8%違う**ため、頭を基準に
              スケール＋平行移動をフィットしてから1回のリサンプルで同一キャンバスへ。
              そのあと talk と同じく口以外を固定（blender/Martin/talkhand_prep.py）

## Blender 側
**キャラ非依存の処理は `blender/lib/` にあります**
（`spriteprep.py` = 位置合わせとパッチマスク、`clip_publish.py` = JSON/GIF 出力）。
Catherine も同じものを使っています。`Martin/publish.py` は lib への薄いシムです。

`blender/Martin/martin_*.blend` … 1コマ1プレーンを重ねて表示切替する構成。
`martin_*_anim.py` の TL（[コマ番号, 保持フレーム数]）を書き換えて実行すれば
タイミングを組み直せます。参照画像はこの develop フォルダのコマ画像です。

元絵は半透明ピクセルを多数含みます。GIFは透明が2値になり縁が汚れるので、
ゲーム本番ではPNGシートを使ってください（GIFは gifまとめ/ に共有用）

## 整列とレンダリングの品質
- **横揺れ対策**: smile / surprised / talk01 / talk02 は**胴体**（下半分のアルファ重心）基準。
  髪の毛は毎コマ形が変わるので、シルエット重心を使うと数pxの横揺れが出ます。
  実測の残り揺れは **1px以下**（対策前の talk02 は 6.5px）。
- **talk の位置固定**: talk は重心では足りませんでした。まず重心合わせの後に
  **顔の帯（メガネ・目）をコマ0と整数相互相関で合わせ直す**二段構えにして、
  顔の残り揺れを 0〜1px にしています（grid_prep.py の refine）。
  ただし talk の20コマは20枚の別々の手描きなので、**位置を合わせても輪郭が毎コマ
  1〜2px描き直されていて全身がボイリングします**（髪の縦ずれ実測2.3px、
  頭と胴体の位置関係が約3pxずれた外れコマも2枚）。位置合わせでは消せません。
  そこで **freeze_talk.py** で「基準コマ（medoid＝コマ15）に各コマの口だけを貼る」
  構成にしました。20種類の口形はそのまま、それ以外は**全コマ完全に同一画素**です
  （実測：口・目の窓の外は全コマ差分 0）。まばたきはコマ7だけ目を戻して1回残しています。
  - 口のマスクは頬の内側をなぞったポリゴン。下のアゴ線と右の輪郭線をまたぐと
    そのエッジがゴーストするので、必ず内側に置くこと。
  - ぼかしはガウスではなく**多角形を収縮させた有限長のランプ**。ガウスだと裾が
    5%残り、250階調のエッジに掛かると12階調のちらつきとして見えます。
- **talkhand の位置固定**: 同じ手口（talkhand_prep.py が freeze_talk のマスク処理を再利用）。
  こちらは別生成の8枚なので拡大率のフィットが先に必要でした。
  上げた手は基準コマのポーズで固定です。8枚は手の位置が少しずつ違いますが、
  **どこで切っても腕の輪郭が合いません**（x=450 の断面で腕の上端がコマ間で32px動く）。
  腕を差し替えると輪郭に段差が出ますし、右半身ごと差し替えるとジャケットの
  ボイリングが戻ってきます。手も動かしたい場合は、腕だけを別レイヤーにして
  肘を軸に数度回す方式（＝手描きの差し替えではなく手続き的な動き）が必要です。
- **anger の位置固定**: talkhand と同じ手口（anger_prep.py）。別生成の10枚なので
  拡大率(1.000〜1.032)と平行移動を先にフィットします。基準は**眼鏡と目の帯**で、
  L1ではなくFFTのSSDマップで探索しています（141x141の探索窓×31段階の拡大率を総当たり
  すると遅いため）。**顔で合わせて胴体で合わせない**のは、胴体は基準コマからしか
  取らないので、フィットが正しくする必要があるのは口のパッチだけだからです。
  口のマスクは三方をふさがれていて余裕がありません: 上は**鼻**（下端 y=217、しかも
  コマ間で平均25/255も描き直される）、右は**輪郭線**（y=238 で x=347、y=250 で x=338 まで
  寄ってくる）、下は**アゴ線**（x=280 で y=253）。10枚の口の和は x 292..337 / y 222..249 なので、
  左の平らな頬を大きく取り、右は鼻の下に潜り込ませ、y=240 より下は絞る形になっています。
- **joy の位置固定**: anger と同じ手口（joy_prep.py が anger_prep のフィットを再利用）。
  違うのはパッチの形で、コマ5/6には**頬の赤み**が付き、コマ5の笑いはアゴのすぐ手前まで
  開くので、口だけのマスクでは赤みが落ち笑いが欠けます。そこで口と赤みを**1枚の多角形**に
  まとめ、毎コマ描き直される4つのものの隙間を縫っています:
  眼鏡の下フチ（y 204..205）／鼻（下端 y 216、x 333..340 だけ 217、左端 x 327）／
  アゴ線（x 265 で y 246、x 294 で y 258 と左ほど高い）／右の輪郭線（y 240 で x 344）。
  鼻の下端(217)とコマ5の笑いの上端(219)の間は**1行しかない**ので、
  x=324 で真下に落として y=218 を通し、ぼかしランプは3ではなく**2**にしています。
  検証は「ランプのリング上でコマ間の差を測る」方法で、最大 42/255・平均3〜7、
  10枚すべての口の画素がマスクの実部に入っています。
- **joy にまばたきが無い理由**: コマ5は目を閉じて笑っていますが、**眼鏡そのものが
  描き直されて**いて、縁の重なり(IoU)がベースに対し 0.58（他コマは 0.84〜0.90）。
  talk/talkhand のまばたき差し替えは「継ぎ目が両者同一の眼鏡のフチに来る」から
  見えないので、フチが違うこの素材では成立しません。
- **sadness の位置固定**: anger / joy と同じ手口（sadness_prep.py）。パッチは**2枚**で、
  口（x 301..326 / y 229..240 と非常に小さい）と、コマ5だけの**涙**（x 262..271 / y 205..221）。
  離れているので1枚にまとめず別多角形にしています（まとめると毎コマ描き直される鼻をまたぐ）。
  涙は**眼鏡のフチを貫いて**描かれていますが、フチの下端はコマごとに違う
  （コマ4は y202、コマ9は y205）ため、フチまで届くパッチは描き直されたフチごと
  持ち込んでしまいます。そこでパッチはフチの1行下 y206 から始め、涙は目尻ではなく
  レンズのすぐ下から始まって見えます（127px中12px分の妥協）。
  リング上のコマ間差は最大13/255・平均2〜3（上回るのは上記の涙の上端5pxのみ）。
- **pleasure の位置固定**: anger / joy / sadness と同じ手口（pleasure_prep.py）。
  この素材は生成が非常に揃っていて、10枚中9枚が scale 1.000・8枚が shift 0 でした。
  パッチは口とコマ6の赤みを**1枚の多角形**にまとめています。間の頬は平らで、
  10枚の一致が6階調以内なので、まとめて写しても何も起きないためです。
  避けているのは眼鏡の下フチ(y203..204)／鼻(左端 x328・下端 y218)／
  アゴ線(x265 で y247)／右の輪郭線(y236 で x347)の4つ。
  リング上のコマ間差は最大22/255・平均2で、**40を超える画素はどのコマにも無し**。
- **surprised02 でベースを medoid にしなかった理由**: パッチできるのは口だけで、
  目は眼鏡ごと描き直されているため差し替えられません（joy のまばたきと同じ判定基準：
  最良オフセットでの縁マスクの IoU。ここでは見開いたコマが 0.67〜0.75）。
  見開いた目を捨てないために、medoid（コマ0＝普通の目）ではなく**コマ4をベースに固定**。
  これが安全なのは、**継ぎ目の品質がベースの選び方にほとんど依存しない**ことを
  先に確認したからです（10通りすべてでリング上の差は最大11〜16/255・40超えゼロ）。
  ベースは「表情として何を保持したいか」で選んでよい、という例。
- **粗さ対策**: Blenderのカメラを `ortho_scale = プレーンの高さ` にして、
  レンダー解像度＝元コマの画素数（1:1）にしています。以前は0.9倍に縮小されて
  再サンプリングが入り、ドットが不均一になっていました。
