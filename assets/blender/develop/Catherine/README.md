## コマ番号の意味
- talk01 : 喋る。0/8=口を閉じる 7/1/6/2=小〜中 3/5/4=開く（4が最大）。
           タイムラインは3フレーズ構成で、各フレーズは保持2フレーム（毎秒12枚）で
           形を混ぜ、区切りで閉じた口に着地します。
           **落ち着いたテンポにしたい場合は timeline の保持を全部 2→3 に**（毎秒8枚）。
- talk02 : 喋る（**手を差し出したポーズ**）。8/0=口を閉じる 7/1/2/3=小〜中 6/5/4=開く（4が最大）。
           手はベース（コマ0）の位置で固定され、動くのは口だけです。
           顔の位置は talk01 と同じなので、基準の帯も口の多角形も同じものを使っています
           （仮定せずこの9枚で検証済み: 口の画素は全コマ実部に入り、リング上の差は最大15/255）。
           タイムラインは talk01 と同じ3フレーズ構成。
- joy    : 喜ぶ（9コマ）。0/5/8/1=口を閉じた笑み 4/6=開く 2/3/7=声を出して笑う（7が最大）。
           **9枚とも頬に赤みが入っている**ので、赤みは専用のパッチを作らずベースに凍結して
           あり、クリップ中ずっと出ています。動くのは口だけ。**歯はどのコマにもありません**
           （コマ7の口の中にエナメルの照りが8pxだけ残っていたので、そこだけ塗り潰し）。
           **位置合わせの基準は目ではなく鼻と頬の帯**です（後述）。
- anger  : 怒る（10コマ）。8/0/9/7/1=への字の口 2/6=**歯を食いしばる** 3/4=開く 5=怒鳴る。
           口以外は固定で、動くのは口だけ。**歯は残してあります**（joy とは逆）:
           joy では同じ開き具合のコマに歯があったり無かったりして点滅しましたが、
           anger では歯そのものが表情です。タイムラインで **2→6 を連続ブロック**にし、
           **5 は 3→4 を経て到達**させているので、歯は2回だけ「保持される拍」として現れ、
           同じ開きの歯無し口と交互になりません（JSON の teethFrames）。
           消したい場合は anger_prep.py で SP.hide_teeth を呼べばすぐ変えられます。
           **目・眉は固定**です（後述）。
- sadness : 悲しむ（10コマ）。**乾いた悲しい顔から始まり、途中で涙が徐々に出ます**。
           0/1/2/3/4/9=完全に乾いている（口だけ震える）
           5=まつ毛の端に玉(15px) 8=ふくらむ(45px) 6=頬を伝う(111px) 7=滴が離れて落ちる(62px)。
           タイムラインは「乾いた顔→玉→ふくらむ→伝う→**落ちる(8フレーム保持)**→
           涙は落ちて消え、ループ」。涙が消えることでループの継ぎ目が自然になります
           （JSON の tearFrames / dryFrames / sobFrame）
- pleasure : 上機嫌（10コマ）。9/8/2/0/5/3/1=閉じた笑み 7/6=開く 4=最大。
           **10枚とも頬に赤みが入っている**のでベースに凍結（クリップ中ずっと出ます）。
           **歯は残してあります**: joy と違って開き具合に比例して増えるので
           （閉じた7枚が5〜24px → 42 → 66 → 92）点滅しません（JSON の teethFrames）。
           **コマ5のウインクが入っています**（JSON の winkFrame／5フレーム保持）。
           コマ3もウインクしますが継ぎ目が3〜4倍悪いので口だけ使用（後述）
- surprised : 驚き（9コマ）。8/0/7=細い線 1/6/5=少し開く 2/3=丸い「お」 4=大きく息を呑む。
           **見開いた目のコマ4をベースに固定**してあり（medoid ならコマ1＝普通の目）、
           クリップ全体が目を見開いたまま動くのは口だけ（Martin の surprised02 と同じ作り）。
           リング上の差はどのコマをベースにしても 6〜8/255・40超えゼロなので、
           ベースは表情だけで選べます。驚きに予備動作は無いので、2カットのあと
           **いきなりコマ4へ跳ね**、揺れてから順に戻ります。
           ※「通常の表情から驚く」版（コマ2/3/4 に目のパッチ）も作りましたが、
           **この見開き固定版を採用**しました（手口は下の技術メモに残してあります）
- joy    : （続き）コマ4（半目）とコマ5（**目を閉じてにこっ**）は**目もパッチしています**
           （JSON の eyeFrames / squintFrame）。
           タイムラインは2拍子: 「微笑み→開く→笑う→2回ゆらす」のあとに
           「半目(4)→**目を閉じてにこっ(5)を6フレーム保持**→開く(4)」。
           表情の保持なので、口パクの2フレームでは短すぎます

## walk（正面歩き・10コマ・全身）

**他の7本と作りが違います。** 表情クリップは1枚のベースに凍結して口や目だけ差し替えますが、
歩きは脚も腰も上着も全部動くので**凍結できる場所がありません**。実測でも、10枚の差分を
40pxブロックで平均すると 頭79 ／ 胴103 ／ 脚59（/255）、ブロック平均は40〜235で、
静かな領域がひとつもありません。凍結案は2つ作って計測し、どちらも破棄しました（4枚版のとき）。

- **太ももを横一直線で切る案**: 局所補正で外側の輪郭は 4〜5px → 0〜3px まで詰まりますが、
  **内側が付いてこない**（その高さでは既に脚の位置が違う）ので脚の間の陰影が継ぎ目で段になる
- **下半身の差分パッチ案**: 脚の移動量が大きすぎて、マスクの縁が乗るべき「既に一致している領域」が
  存在しない。リングの40超えが **271〜468px**（pleasure のウインクは24px）

そこで **10枚をそのまま回します**。代わりにフィットを詰めてあります。

### スケールは「採点」ではなく「実測」
枠を1つ採点する方式は全身では効きません。顔だけだと**髪のかかり方が毎回違うのでマッチが甘く、
スケールが与えた範囲の上限まで暴走**します。腹だけ（x535..625 y430..560＝開いた上着が
どのコマでも覆わない唯一の帯）は4枚版では通ったのに10枚では破綻し、**誤差曲線が平坦**
（スケール1.11〜1.19 でずっと23〜24/255）。平らな肌と水平なウエストバンドは、拡大しながら
ずらすとどこまでも一致してしまうためです。2枠を同時に採点しても、コントラストで重みが付くので
数枚が3〜5%大きく出ました。

**そこで顔と腰の枠を別々に位置決めし、その間隔（290px）とコマ0の間隔の比をスケールにします。**
比なので、どちらの枠がどれだけよく一致したかは効きません。平行移動は顔から取ります
（頭が動かないことが最優先）。フィットが見ていない landmark で検算した結果:

| | 採点方式 | **実測方式（採用）** |
|---|---|---|
| 目→ウエストバンド のばらつき | 9.4px (5.0%) | **3.9px (2.1%)** |
| 目→ショーツ裾 のばらつき | 16.7px (6.0%) | **8.9px (3.2%)** |
| 最下点（靴底）のばらつき | 64px | **42px** |

頭の止まり方はどちらも同等（10枚の虹彩が x 3.7px・y 1.7px 以内）。
10枚は互いに 1.00〜1.11 倍の大きさで描かれていて、コマ0がいちばん小さいです。

### 再生順は素材の並び順ではありません
歩行位相を実測して決めました。**前足＝靴底が低い方**（正面なので手前の足）、
**前後の距離＝前後の靴の面積比**（手前の靴が大きく描かれる／スケールに依らない読み方）。
これで5枚ずつ2つの半周期に分かれ、各半周期は接地→すれ違いへ進みます。

| 半周期 | 順番（括弧内は靴の面積比） |
|---|---|
| 左足が前 | 9 (1.84) → 8 (1.76) → 3 (1.78) → 4 (1.68) → 5 (1.36) |
| 右足が前 | 6 (1.81) → 2 (1.78) → 7 (1.63) → 0 (1.61) → 1 (1.31) |

さらに脚領域の画素差で**半周期が連続になる28800通りの巡回路を全探索**して裏取りしました。
接地→すれ違いを守る中での最小がこの順（コスト203.0）。全体最小は200.0（1.5%だけ小さい）
ですが、**片方の半周期を逆走する**ので歩きになりません。
コスト40と34の2ステップが2回の着地（後ろ足が地面を離れて振り出される所）で、
残り8ステップは11〜23です。

→ **9 → 8 → 3 → 4 → 5 → 6 → 2 → 7 → 0 → 1 →（ループ）**

### テンポ（保持を左右対称に不均等にしています）
10コマ＝1周期＝2歩。**均一な保持だと2択しかありません**（保持は整数フレームのため）。

| 均一保持 | 1周期 | 歩調 | |
|---|---|---|---|
| 2 | 0.83s | 毎分144歩 | 急いで見える |
| 3 | 1.25s | 毎分96歩 | のんびり |

そこで**不均等**にしています。接地直後の2カットを3フレーム（体重が乗る＝両足接地でゆっくり）、
振り出しの3カットを2フレーム。半周期12F・**1周期24F＝ちょうど1.00秒＝毎分120歩**で、
普通に歩く速さです。接地を長く持つのは妥協ではなく、歩きのタイミングそのものです。

```
TL = [(9,3), (8,3), (3,2), (4,2), (5,2),      # 左足接地 → 右足が振り出される
      (6,3), (2,3), (7,2), (0,2), (1,2)]      # 右足接地 → 左足が振り出される
```

**規則は1つだけ: 左右の半周期に同じパターンを入れること。** 違えると足を引きずって見えます
（`catherine_walk_anim.py` に assert を入れてあります）。速くするなら `SLOW` `FAST` を両方2
（0.83秒・毎分144歩）、遅くするなら両方3（1.25秒・毎分96歩）。JSON と GIF は anim を読むので
自動追従します。

### 縦のぶれ止め（相似変換では取れないので、縦だけ区分的に伸縮）
フィットで頭を合わせただけでは足りませんでした。**胴（目→裾）は3.3%しかぶれないのに、
脚（裾→靴底）は11.6%ぶれます**。しかも同じ動きであるはずの左右の半周期が食い違っていました。

| 半周期の位置 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 左足が前 の脚長 | 354 | 349 | 363 | 377 | 391 |
| 右足が前 の脚長 | 374 | 359 | 353 | 354 | 355 |

これが縦揺れの正体で、**拡大縮小と平行移動では取れません**（10枚が違うプロポーションで
描かれているため＝相似変換ではない）。そこで**縦スケールを2つの行で切り替え**ます。

- 目より上 … 素のまま（頭はフィットが置いた位置のまま）
- 目 → ショーツ裾 … 胴の長さが全コマ平均になるように伸縮
- 裾 → 下 … **半周期の同じ位置どうしが同じ脚長になる**ように伸縮

写像は両方の行で連続なので**継ぎ目は出ません**。倍率は胴 0.985〜1.018・脚 0.954〜1.051 と
穏やかです。結果:

| | 前 | 後 |
|---|---|---|
| 胴の長さのばらつき | 3.3% | **0.5%** |
| 脚の長さのばらつき | 11.6% | **5.5%**（残りは歩幅そのもの・左右の半周期が1行以内で一致） |
| 靴底のばらつき | 42px | **21px** |

元々1回だけ行っていたリサンプル（元絵1402px → 724px）に畳み込んでいるので、**鮮鋭度は
変わりません**（縦のソフトエッジ率 17.0〜18.1% → 16.9〜18.2%）。

仕上げに、**髪を含まない目と鼻の枠で整数1px単位の微調整**を掛けています。フィットの平行移動は
髪の入った枠から来ていて、髪は毎回違うので1〜2pxずれるためです（虹彩のばらつき 3.8px → 2.9px）。

**残るのは髪と上着のボイリングだけ**です。10枚が別々に生成されている以上、位置合わせでは
消せません。

### 順番の食い違い防止
`walk_prep.py` は歩行位相を実測して求めた再生順を `walk_cycle.json` に書き出し、
`walk_publish.py` が anim の TL と突き合わせます。食い違ったらパブリッシュは失敗します。

## JSON
```
timeline : [コマ番号, 表示フレーム数] の配列（Blenderのタイムラインと同じ値）
frames   : 1フレーム=1要素に展開済みの配列（index でそのまま引ける）
fps / frameWidth / frameHeight / frameCount / loop / durationSec / labels / baseFrame
```

## 最小実装
```js
const d = await (await fetch("catherine_talk01.json")).json();
const img = new Image(); img.src = d.sheet;
let t0 = performance.now();
function draw(now) {
  const f = Math.floor((now - t0) / 1000 * d.fps) % d.frames.length;
  const i = d.frames[f];
  ctx.clearRect(0, 0, d.frameWidth, d.frameHeight);
  ctx.drawImage(img, i*d.frameWidth, 0, d.frameWidth, d.frameHeight,
                0, 0, d.frameWidth, d.frameHeight);
  requestAnimationFrame(draw);
}
```
拡大時は canvas に `image-rendering: pixelated` を付けてください。

ゲーム本番ではPNGシートを使ってください（GIFは `../../gifまとめ/` に共有用）。

## Blender 側
`blender/Catherine/catherine_*.blend` … 1コマ1プレーンを重ねて表示切替する構成。
`catherine_*_anim.py` の TL（[コマ番号, 保持フレーム数]）を書き換えて実行すれば
タイミングを組み直せます。

- `talk01_prep.py` / `talk02_prep.py` / `joy_prep.py` … 位置合わせ＋凍結
- `talk01_publish.py` / `talk02_publish.py` / `joy_publish.py` … JSON と GIF を出す
  （TL は anim スクリプトから読むので二重管理なし）

**キャラ非依存の処理は `blender/lib/` にあります**
（`spriteprep.py` = 位置合わせとパッチマスク、`clip_publish.py` = JSON/GIF 出力）。
Martin のクリップも同じものを使っています。

## 位置合わせと凍結
各クリップの9枚は「同じポーズの別テイク」で、輪郭が毎コマ1〜2px描き直されているため、
そのまま並べると全身が沸き立ちます（ボイリング）。位置合わせでは消せないので、
**1枚のベース（medoid。talk01 はコマ5、talk02 と joy はコマ0）に各コマの口だけを貼る**
構成にしています。実測：口のパッチ（talk は1290px、joy は1906px）の外は全コマ差分ゼロ。

- **基準は目と鼻梁の帯**。Catherine は眼鏡が無く、髪が巨大で毎コマ描き直されるため、
  剛体として使えるランドマークは目だけです（Martin は眼鏡の帯）。
- 口のマスクは頬の内側をなぞった多角形。避けているのは
  鼻（下端 y233・右端 x268）／左のアゴ線（y258 で x249、y271 で x274）／
  右のアゴ線（y262 で x316、y271 で x307）。
  大きく開いたコマ（2と4）の**アゴのシワはわざとパッチの内側**に入れています
  （口の形の一部なので）。
- **joy だけ基準が違う**: コマ5は目を閉じて笑うので、目の帯をテンプレートにすると
  合わせようがなく、探索が拡大率の端まで走ります（scale 1.100・shift -57,-61・rms 73）。
  **目の下の帯（鼻・両頬・口／source x430..700 y400..560）**に変えると9枚とも収まり、
  目基準で合った8枚とも source で5px以内に一致します。口の隣なので基準として妥当です。
- **sadness の涙は「色」で抜いています**（`spriteprep.colour_patch`／3種類目のパッチ）。
  手引き多角形は継ぎ目を置く静かな肌が要りますが、涙は下まぶたに密着していて置き場が無い。
  joy の差分マスクは「変化した領域に静かな縁」が要りますが、まぶた・まつ毛・髪が
  毎コマ描き直されるので成立しない（リングの40超え 47〜219px／joy は 5〜25）。
  ベースを涙ありのコマに差し替える手も、コマ2→コマ7で**図の15%が跳ねる**ので不可。
  **しかし顔の中で青いのは涙だけ**です。色で抜けば継ぎ目は涙自身の輪郭だけになり、
  それは平らな頬の上に乗ります（まぶたはベースのまま＝涙がまつ毛に重なった状態）。
  「ベースのまぶたの下端より下に届く塊だけ残す」条件を付けると、
  白目のハイライトが動いただけのコマを涙と誤検出しません（残り6枚は正しく乾き判定）。
- **surprised は見開いたコマをベースに固定しました**（採用版）。目のパッチも作れます（下記）が、
  最終的にはこちらを採用しています。**どのコマをベースにしてもリング上の差は 6〜8/255・
  40超えゼロ**なので、ベースは継ぎ目でなく表情だけで選べます。
- 以下は**採用しなかった「通常→驚き」版**の記録です（戻す場合の手順）。
  **見開いた目は「片目ずつ」パッチします**。pleasure のウインクと同じ手順
  （目を含まない帯＝鼻と口で局所補正してから差分を取る）ですが、**両目を一括にすると
  161〜411px** で破綻するので片目ずつに分けます。リングの40超えは 129〜216px
  （pleasure のウインクは24px）で、これは「両目が見開いて両方の眉も上がる」＝顔の上半分が
  本当に変わっているためです。
- **そのままだと前髪まで差し替わります**。コマ4の変化 6900px のうち 1100px が目の真上の
  前髪でした。**前髪が1px動くと「髪型がピクッとする」ように見えて、消したかったボイリングより
  悪い**ので、マスクから髪を引いています。
  髪は顔の中で唯一はっきり黄色く、**G−B が前髪 106 に対し肌は 36** なので色で取れます。
  3px太らせて（暗い輪郭も守る）ベースと元コマの両方の髪を差し引くと、前髪はベースの画素の
  まま固定され、継ぎ目は髪の縁＝両側とも平らで同一の肌の上に落ちます。
  **髪の変化画素は 1100 → 0**（全9コマで実測0）。目の上に残る約210pxは眉で、これは動くべき
  ものです。`spriteprep.colour_region` ＝ colour_patch（色で抜いて乗せる）の逆で
  「**色で抜いて守る**」。
- **pleasure のウインクは「パッチ直前に局所補正」で入りました**（`spriteprep.refine_shift`）。
  joy の差分マスクをそのまま当てると失敗します（リングの40超え 116〜258px）。この素材は
  フィットが scale 1.036・shift 14px までばらつくので、**グローバルなズレが「変化」として
  読まれ**、パッチが上半身全体に広がってしまうからです。clip 全体を目基準で合わせ直すのは
  逆効果（rms 33〜71、リング 239〜412px。コマ3/5 は片目を閉じていてテンプレートが合わない）。
  **正解はパッチのためだけに局所補正すること**: ウインクしていない側の目と鼻梁で整合を取って
  整数画素シフトし、それから差分を取る。残るのはウインクそのものです。
  コマ5は 24px（joy 並み）まで下がり、変化2132pxのうち髪の帯はわずか250px。
  コマ3は 90〜104px と3〜4倍悪いので使っていません。
  **補正の基準領域にはパッチ対象を入れないこと**（入れると特徴自身がフィットを支配します）。
- **anger の目・眉はパッチできません**: コマ4/5で眉が鋭くなる（目まわりの差分が5500px、
  他は2400〜3800px）ので joy と同じ差分マスクを試しましたが、**この素材は上半身全体が
  描き直されていて**（髪の輪郭が全部ずれる）、継ぎ目を置ける静かな場所がありません。
  リング上の40超えが 97〜209px（joy は 5〜25px）。目基準で合わせ直しても 97〜140px で
  改善しませんでした。素材の揃い方次第で「できる／できない」が変わる、という例です。
- **joy の目は「差分から作ったマスク」でパッチしています**（`spriteprep.diff_patch`）。
  **手で多角形を引くと必ず失敗します**: 目のまわりはまぶたの折り目・まつ毛・前髪に
  囲まれていて、多角形はそのどれかを横切るしかなく、ぼかしランプが
  「両コマで食い違うエッジ」にまたがってゴーストします（実測 237〜252/255）。
  代わりに**そのコマが変えた画素そのもの**をマスクにして太らせると、
  継ぎ目は自動的に「両コマが一致している場所」に落ちます。
  実測 コマ5で 133/5.1（40超えは前髪の25px）、コマ4で 101/3.7。1:1では見つけられません。
  talk / talkhand のまばたき差し替えと同じ考え方を一般化したものです。
  箱は**太らせたマスクが縁に触れない大きさ**にすること（触ると箱の縁が継ぎ目になります）。
- **joy の口は斜め**: 上端が x272 で y237、x304 で y226 と右へ行くほど上がるので、
  水平な上辺を低く取ると大笑いが欠けます。平らな頬の上を高く広く取り、
  左だけ鼻（下端 y233・右端 x268）の下に潜らせています。
- 良し悪しの検証は「ぼかしランプのリング上でコマ間の差を測る」方法。
  talk は最大10〜15/255、joy は最大11/255、いずれも40を超える画素はどのコマにもありません。
- ぼかしはガウス禁止（裾が5%残り、250階調のエッジで12階調のちらつきになる）。
  多角形を収縮させた有限長のランプを使っています。

## 歯の消し方（joy のみ）
テイクによって歯を描いたり描かなかったりするので、開き具合が同じコマ同士を切り替えると
歯が点滅します。判定は**「明るいのに赤くない」**: 口を作っている色はどれも赤く
（舌 242,103,85 と上顎 210,60,58 はどちらも R-(G+B)/2 が約150、縁は赤いが暗い）、
エナメルだけが 255,255,255 から 226,130,126 の縁までずっと120未満です。
**彩度ではなく明度＋赤さで判定するのがコツ**で、彩度だと半端に白い縁を取りこぼして
塗り跡が灰色く残ります。さらに縁は舌の赤さ(148)と地続きで閾値では切れないため、
検出した帯を**2px太らせてから**塗ります（太らせた分は元々上顎か舌なので実害なし。
暗い画素は除外して縁のラインは残す）。塗り潰しは「歯でない隣接画素の平均」を
繰り返すだけなので、上の暗赤と下の舌が内側へ伸びてきて、歯を描いていないコマと
同じ見た目になります。
